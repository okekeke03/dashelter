# 設計メモ

## 判定の流れ

```
現在地 → 警報レベル + 危険区域の内か外か → ルールで判定
                                       ├ 安全:とどまる
                                       ├ 準備:避難の準備
                                       └ 避難:避難所を案内
                                              ↓
              判定結果と事実データ → AI が説明・アドバイスを作る → 出力を検証 → 表示
```

デモモードは、この流れの「入力」(警報・雨量など)だけを仮データに差し替える。判定処理と画面は本番と同じものを使う。

## 判定ルール(`web/src/core/judge.js`)

考え方は内閣府「避難情報に関するガイドライン」にそろえる。**「避難」とは危険な場所から離れること。危険な区域の外にいる人は、避難所へ行く必要はない。**

災害ごとに「現在地の市区町村の警報レベル × 現在地が危険な区域の中か外か」で判定し、一番重いものを全体の判定にする。

| 警報レベル | 危険区域の中 | 危険区域の外 | 区域が確認できない |
|---|---|---|---|
| 5(特別警報) | 緊急安全確保 | とどまる | 判定できない |
| 4(危険警報) | **避難** | **とどまる** | 判定できない |
| 3(警報) | 準備 | とどまる | 判定できない |
| 2(注意報) | 注意 | 注意 | 注意 |
| なし | 安全 | 安全 | 安全 |
| 取得できない | 判定できない | 判定できない | 判定できない |

| 災害(気象庁の警報) | 見る区域(重ねるハザードマップ) | 案内する避難場所の種別 |
|---|---|---|
| 大雨(浸水害) | 洪水浸水想定区域・内水浸水想定区域のどちらか | 洪水 または 内水氾濫 |
| 土砂災害 | 土砂災害警戒区域(土石流・急傾斜地・地すべり) | 崖崩れ、土石流及び地滑り |
| 高潮 | 高潮浸水想定区域 | 高潮 |

画面の表示:

- 一番大きな文字は「何をすべきか」。警報レベルはその下の補足にする。
  - 避難:「ここは危険な区域です。今すぐ避難してください」
  - とどまる:「ここは危険区域の外です。移動せず、今いる場所にとどまってください」(「自治体から避難指示が出たらそれに従う」を必ず添える)
- 建物の上の階への避難(屋内安全確保)は、水害で、浸水 3m 未満・家屋倒壊等氾濫想定区域の外・どちらも確認できた場合だけ選択肢として伝える。土砂災害では案内しない。
- 洪水浸水想定区域の中では、判定とは別に「川ごとの氾濫情報はこのアプリでは判定していない」と表示し、「川の防災情報」(国土交通省)へリンクする。
- どの判定でも「この判定は公的機関のデータにもとづく参考情報です。最終的な判断はご自身で行い、自治体の避難指示や周りの状況を優先してください。」を表示する。

## 警報・区域データについて分かったこと(2026-10-19)

- 気象庁は 2026-05-29 に「新たな防災気象情報」へ移行した。旧形式の JSON(`bosai/warning/data/warning/`)は 2026-05-28 で更新が止まっている。新形式は `bosai/warning/data/r8/{府県予報区}.json`。
- 警報の種類コードは、気象庁防災情報XML のコード管理表(2026-10-19 版)で確認した。大雨 10/03/43/33、土砂災害 29/09/49/39、高潮 19/08/48/38(レベル2/3/4/5)。
- データの中に該当地域が見つからない場合は、形式が変わった可能性があるので「発表なし」とはみなさず「判定できない」にする。
- ハザードマップのタイルは CORS で読み込める。色の値は東京都内の実タイルで確認した。凡例にない色(古い凡例のデータなど)は「区域の中・深さ不明」として扱う。
- 国土地理院の住所検索(逆ジオコーダ)は CORS に対応していないので、ブラウザから直接は呼べない。サーバー処理(Cloudflare Functions)経由で呼ぶ。

## 避難場所データの空白(重要)

東京都の 62 区市町村のうち、**17 区市町村では大雨に関係する避難場所がデータ上 1 件もない**(2026-10-19 時点)。

- 指定緊急避難場所データを公開していない(指定避難所のみ公開・未登録): 墨田区、江東区、渋谷区、葛飾区、武蔵野市、奥多摩町、利島村、青ヶ島村
- データはあるが、洪水・内水・高潮・土砂災害の指定が 0 件: 新宿区、文京区、足立区、江戸川区、調布市、小金井市、武蔵村山市、大島町、新島村

浸水リスクが特に大きい江東5区(墨田・江東・足立・葛飾・江戸川)がすべて含まれる。実際に江戸川区役所の地点で試すと、条件に合う一番近い避難場所は約 6km 先(荒川区)になった。江戸川区などは大規模水害時に区外への「広域避難」を方針としており、区独自の計画を確認してもらう必要がある。

**画面での扱い(決定):** 現在地の区市町村に必要な種別の避難場所がデータ上ない場合は、その旨と「わがまちハザードマップ」へのリンクを表示したうえで、他の区市町村の避難場所を「〇〇区の避難場所」と明示して表示する。何も出さないより、選択肢があるほうが行動しやすいため。指定避難所(滞在用の施設)での代用は、水害に安全とは限らないので行わない。

## 画面(`web/`)

- ビルドなしの静的サイト。地図は Leaflet 1.9.4 を `web/vendor/` に同梱(公式の SRI ハッシュと一致することを確認済み)。
- 外部データ(避難場所名・備考など)は必ず `textContent` で表示し、HTML として解釈させない。
- `web/_headers` で CSP などのセキュリティヘッダーを付ける。開発用サーバーも同じヘッダーを付ける。
- ハザードマップの判定は、現在地の周り ±2 ピクセル(ズーム16で約±5m)を調べ、1つでも区域の中なら中とする(GPS の誤差を考えて安全側に倒す)。
- 「Google マップで徒歩ルートを開く」は `dir_action=navigate` 付き。目的地にピンが立ち、スマホではそのままナビが始まる。
- 備考に「開設しない」などの条件がある避難場所は、条件のない避難場所より後ろに並べる(上位3件に入らないことが多い)。

## 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| 避難判断 | ルールで決める(警報+ハザードマップ) | 命に関わる判断を AI に任せない |
| AI の役割 | 説明と行動アドバイスだけ。出力は検証する | 事実データにない内容を出させない |
| 失敗時の値 | 「不明」と表示する | 0m・0mm を事実のように見せない |
| 範囲 | まず東京都全域。設計は全国対応を前提にする | 全国約10万件は、表示範囲・現在地周辺だけを取りに行けば扱える |
| 画面 | 静的サイト + 小さなサーバー処理 | 無料で公開でき、スリープしない |
| データ整形 | Python(標準ライブラリのみ) | 前処理だけなので、使い慣れた言語を使う |
| データの分割 | 2次メッシュ(約10km四方)ごとのファイル | 現在地のメッシュと周り3×3マスだけを読めば済み、全国に広げても1回の読み込み量が増えない |
| 出典と注意事項 | 国土地理院「ご利用上の注意」の要点を `index.json` に含め、画面にも表示する | 第三者に提供するときは注意事項を正確に伝えるよう求められている |

## 避難所データについて分かったこと(東京都、2026-10-19 取得)

- 東京都の指定緊急避難場所は 2,272 件。除外が必要なデータ(座標の欠け・範囲外・ID の重複)は 0 件
- 大雨に関係する種別:洪水 1,361 件、内水氾濫 1,121 件、崖崩れ・土石流・地滑り 976 件、高潮 311 件
- 2次メッシュ 39 個に分かれ、1 メッシュあたり中央値 28 件・最大 261 件(最大のファイルでも約 50KB)
- **備考に条件付きの記載がある。** 台東区の 14 か所は「洪水」対応だが、「荒川が氾濫するおそれがある場合は開設しない」と書かれている。種別のフラグだけで案内すると、閉まっている避難所に誘導してしまう。→ 「2. 判定」で扱いを決める
- 備考には想定収容人数(地震・風水害)が書かれているものもある(一部の区のみ)

## プロトタイプからの主な変更点

- AI が判定していた「避難が必要か」を、ルールによる判定に置き換える
- 別々の HTML だった「安全/準備」画面を1つの画面に統合する
- 提供が終了したモデル(gemini-1.5-flash)と古い SDK をやめる
- 避難所の標高は検索のたびに API で取得せず、前もって計算しておく
- `debug=True` での公開、`innerHTML` へのそのままの挿入などの危険箇所をなくす
